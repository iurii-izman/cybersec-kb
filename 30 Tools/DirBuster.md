# DirBuster

## Что это

DirBuster — GUI-инструмент для dictionary-based поиска web directories и files.

## Для чего нужен

Помогает выполнять [[Content Discovery]], управляя base URL, [[Wordlists|wordlist]], extensions, threads и recursive behavior через графический интерфейс.

## Когда использовать

В разрешённой лаборатории, когда удобнее наблюдать и фильтровать активный поиск через GUI. Выбор GUI не меняет логику техники и требования к интерпретации.

## Связанные техники

- [[Content Discovery]]
- [[Web Enumeration]]

## Базовый синтаксис

DirBuster запускается как GUI-приложение. Минимальные входные данные:

```text
Target URL: http://TARGET/
Wordlist: /path/to/wordlist.txt
```

## Основные команды

### Запустить контролируемый поиск

**Goal:** найти candidate paths на учебном web-приложении.

**Action:** указать `http://TARGET/`, выбрать релевантную wordlist, установить умеренную concurrency и начать scan.

**Evidence:** таблица найденных URL с [[HTTP Status Codes|status]], response size и типом ресурса.

**Interpretation:** отличающиеся ответы приоритизируют ручную проверку; они не доказывают доступность чувствительных данных.

**Next step:** открыть выбранный path отдельно, сверить response с baseline и задокументировать только подтверждённое наблюдение.

## Важные параметры

| Параметр | Назначение |
|---|---|
| Target URL | Разрешённый base URL с корректной схемой |
| Wordlist | Кандидаты, подходящие контексту |
| Threads | Уровень параллелизма и нагрузки |
| File extensions | Дополнительные суффиксы при наличии гипотезы |

## Как читать результат

Оценивать status, размер, redirect target и повторяемость ответа. Большое число одинаковых находок часто указывает на custom error page или неверную фильтрацию.

## Важные моменты

- GUI не снимает обязанность понимать [[HTTP]].
- Повышать threads можно только с учётом правил лаборатории и нагрузки.
- Recursive search запускать после подтверждения полезной ветки.

## Типичные ошибки

- Вводить target без схемы или с неверным base path.
- Принимать все `200` за разные реальные ресурсы.
- Использовать большую wordlist до проверки baseline.
