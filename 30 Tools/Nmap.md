# Nmap

## Что это

Nmap — инструмент сетевого обнаружения и исследования доступных сервисов.

## Для чего нужен

Помогает подтвердить доступные TCP-порты и определить, есть ли на разрешённой цели web-сервис для дальнейшей [[Web Enumeration]].

## Когда использовать

В начале работы с лабораторной или иной явно разрешённой целью, когда известен `TARGET`, но неизвестны доступные сервисы.

## Связанные техники

- [[Web Enumeration]]

## Базовый синтаксис

```bash
nmap [options] TARGET
```

## Основные команды

### Проверить типовые TCP-порты

**Goal:** определить доступные сервисы на учебном `TARGET`.

**Action:**

```bash
nmap TARGET
```

**Evidence:** строки с состоянием `open`, например HTTP-сервис на одном из портов лаборатории.

**Interpretation:** `open` показывает, что соединение принимается; имя сервиса — гипотеза, а не доказательство технологии.

**Next step:** проверить сервис подходящим клиентом; для HTTP перейти к [[Web Enumeration]].

### Определить версию найденного сервиса

**Goal:** получить дополнительные признаки сервиса на уже обнаруженном порту.

**Action:**

```bash
nmap -sV -p PORT TARGET
```

**Evidence:** предполагаемые service и version в строке выбранного порта.

**Interpretation:** результат основан на probes и может быть неточным или скрытым proxy.

**Next step:** подтвердить вывод непосредственным взаимодействием с сервисом.

## Важные параметры

| Параметр | Назначение |
|---|---|
| `-p PORT` | Проверить конкретный разрешённый порт |
| `-sV` | Выполнить определение сервиса и версии |

## Как читать результат

Сначала смотреть на host state и состояние порта. `open` означает принимающее соединение, `closed` — достижимый, но не слушающий порт, `filtered` — отсутствие однозначного ответа из-за фильтрации или сети.

## Важные моменты

- Проверять только цели в согласованном scope.
- Разделять наблюдение (`80/tcp open`) и предположение (`http`).
- Начинать с минимально достаточной проверки.

## Типичные ошибки

- Считать предполагаемую версию доказанным фактом.
- Сканировать неверный host или порт из-за ошибки в scope.
- Переходить к web-инструментам, не подтвердив URL и протокол.

## Альтернативы

- Ручная проверка известного порта подходящим сетевым клиентом.

## Где использовал
